# Экспертная оценка безопасности

**Датасет:** github_ip_security_scan v1.0
**Дата сканирования:** 2026-09-28
**Эксперт:** danilkos00

## Область сканирования

Диапазоны IP-адресов сервисов GitHub получены через GitHub Meta API
(api.github.com/meta) с помощью jq: извлечены секции git, web, api —
80 CIDR-диапазонов (raw/github_ips.txt). Важно: Meta API публикует служебные
диапазоны GitHub, а не «личный IP» аккаунта.

Непосредственному сканированию подвергнуты только:

| Цель | Обоснование |
|---|---|
| 127.0.0.1 (Apache 2.4.58 в WSL2) | Собственный ресурс |
| 45.33.32.156 (scanme.nmap.org) | Официальная авторизованная демо-цель Nmap |

Инфраструктура GitHub (диапазоны из Meta API) не сканировалась.

## Методика

- Nmap 7.94SVN: `nmap -sV -sC 127.0.0.1` — полное сканирование с определением версий;
  `nmap -sS --max-rate 100 -p1-1000 45.33.32.156` — SYN-скан с ограничением скорости.
- Masscan 1.0-BETA: `masscan -p80,443,22 45.33.32.156 --rate 100` — скорость
  ограничена 100 пакетами/сек в духе правил GitHub Bug Bounty. Masscan не выполняет
  DNS-резолвинг, поэтому домен заранее разрешён в IPv4 (`getent ahostsv4`).
- Nikto 2.1.5: `nikto -h http://127.0.0.1` и `nikto -h http://45.33.32.156`.

## Критические находки

Не обнаружено.

## Средние находки

1. **Отсутствие заголовка X-Frame-Options** (Nikto, обе цели) — риск clickjacking.
   Рекомендация: `Header always set X-Frame-Options "SAMEORIGIN"`.
2. **Доступный /server-status** (Nikto, 127.0.0.1) — раскрытие служебной информации
   Apache (статистика запросов, обработчики). Рекомендация: `Require local` в блоке
   `<Location /server-status>` и проверка недоступности извне.
3. **Directory indexing в /images/** (Nikto, 45.33.32.156) — просматриваемые списки
   каталогов раскрывают структуру и файлы. Рекомендация: `Options -Indexes`.
4. **Открытый SSH (22)** (Nmap + Masscan, 45.33.32.156) — для собственных серверов:
   IP-whitelist, аутентификация только по ключам, запрет паролей.

## Низкие находки

5. **Открытый HTTP (80)** (Nmap + Masscan) — настроить редирект на HTTPS.
6. **Apache 2.4.58 с дефолтной страницей It works** (Nmap, 127.0.0.1) — обновить
   пакет, удалить дефолтную страницу.
7. **Утечка inode через ETags** (Nikto, обе цели) — `FileETag MTime Size`.
8. **Информативный метод OPTIONS** (Nikto, обе цели) — ограничить разрешённые методы.
9. **Дефолтный файл /icons/README** (Nikto, 45.33.32.156) — удалять дефолтные файлы.
10. **Баннер версии сервера** (Nmap/Nikto) — `ServerTokens Prod`, `ServerSignature Off`.

## Перекрёстная проверка инструментов

Masscan (--rate 100) подтвердил оба открытых порта (22, 80), найденных
Nmap SYN-сканом, — совпадение результатов 100%, ложно-положительных нет.

## Ограничения среды

- Masscan поддерживает только IPv4 и не резолвит доменные имена — цель задавалась
  IPv4-адресом; IPv6-адреса цели не сканировались.
- В WSL2 raw-сокеты зависят от сетевого режима подсистемы; при проблемах
  применяется networkingMode=mirrored либо эквивалент `nmap -sS --max-rate 100`.

## Рекомендации

1. Закрыть все неиспользуемые порты; остановить Apache, если он не нужен.
2. Обновлять серверное ПО (Apache) до актуальных стабильных версий.
3. Добавить security-заголовки: X-Frame-Options, X-Content-Type-Options, HSTS, CSP.
4. Отключить directory indexing, удалить дефолтные файлы и страницы.
5. Ограничить /server-status локальным доступом.
6. Настроить регулярный мониторинг открытых портов (Nmap + алертинг).
7. Включить 2FA на GitHub; ревизия публичных репозиториев на секреты
   (`git log --all --full-history -- "*.env" "*.pem"`).
8. Подключить Dependabot и секрет-сканирование GitHub; добавить SAST (Horusec) в CI/CD.

## Правовое соответствие

- GitHub Bug Bounty Rules: соблюдены ограничения на объём трафика (rate ≤ 100 pps);
  инфраструктура GitHub не сканировалась.
- УК РФ ст. 272: сканирование выполнено только в отношении собственного ресурса
  (127.0.0.1) и авторизованной демо-цели (scanme.nmap.org).
